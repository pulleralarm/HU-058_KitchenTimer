# Kitchen timer firmware for the HU-058D WiFi clock

This is a fork of **misterblack1s** HU-058D WiFi clock firmware to create a three countdown kitchen clock that can optionally be controlled independant of Home Assistant. I also changed the aip33628 component to be more a kind of display component, giving complete control over what is displayed to the yaml file.

Be aware that you will need to adapt the YAML to your needs. This is not a project that allows every preference to be set via Home Assistant.

For extensive documentation about the reverse engineered hardware, please go to [misterblack1's project page](https://github.com/misterblack1/HU-058_ESPHome). Please also have a look at the [Credits](#-credits) that list from which other contributions I took code and inspiration.

## The board variants

| Board | Sold as | Timekeeping |
| --- | --- | --- |
| HU-058D | [ESP8266 IoT Colorful WiFi Clock Kit](https://www.aliexpress.us/item/3256807371597845.html) | ESP-01S, NTP over WiFi |
| HU-058 / HU-058SE | [DIY KIT Electronic Clock LED Microcontroller Soldering Exercise](https://www.aliexpress.us/item/3256806414008654.html) | Dallas RTC and a coin cell |

## User features

- Display current time, temperature and humidity in turn
- Allow up to three parallel countdowns that can be controlled both by Home Assistant and the control buttons
- Signal countdown end using the buzzer
- Signal countdown remaining time and end to Home Assistant for automations
- Ambient light sensor
- Expose the one upper button single click not used internally to Home Assistant for automations
- Send a text to display temporarely from Home Assistant

## Technical features

- Compiles on both ESP8266 and ESP32. I'm using my clock with an ESP8266, ESP32C3 is only software and oscilloscope tested
- Removed all policy decisions when to display the current time from the aip33628 component, leaving helper functions show_text(), show_clock_once(), show_temp_once(), show_hum_once()
- Allow complete control over annunciators
- State machine what to display moved to the YAML file
- Complete MQTT integration, in addition to the HA API. MQTT is what I prefer for devices that are not running 24x7
- The second clock GPIO is now optional. If you're short on pins (hello D1-Mini), you can wire both drivers' clock pins to the same GPIO

## Temperature and humidity

First I used a sht4x sensor attached to the back of the clock. However, the readings were influenced too much by the heat generated by the electronics. So now I've moved the sensor to a light control board and monitor them via MQTT. I also saw a photo where someone mounted the sensor above the USB connector at the left side of the case. Your mileage may vary...

## The conversion

Please look at [misterblack1's description](https://github.com/misterblack1/HU-058_ESPHome). You also need to mount the light sensor and buzzer, and make sure that both are connected to **3.3V, not 5V!**. 
[mrceedjay](https://github.com/mrceedjay/HU-058_ESPHome-NTC-LDR-Buzzer) shows how to achieve this by cutting a trace on the board. I don't use the shipped NTC. Note that the ESP8266 D1 mini has another voltage divider on the analog in pin, reducing 3.3V to the maximum of 1V the chip allows. I don't know whether every ESP8266 has this, **check your board twice**. ESP32 should be able to handle 3.3V analog in.

I wired my ESP8266 D1 mini like this:

| ESP8266 | Socket pin | Net |
| --- | --- | --- |
| GPIO12 | 1 and 14 on HU-058D; 1 and 16 on HU-058 / HU-058SE | CLK, driver 2+1 |
| GPIO13 | 5 | DATA, driver 1 |
| GPIO14 | 2 | DATA_1, driver 2 |
| GPIO2 | 11 | R_B, buzzer |
| GPIO3 | 9 | S1, top button |
| GPIO0 | 10 | S2, bottom button |
| GPIO17 | 4 | R_P, LDR |
| GND | 8 | GND |

GPIO4+GPIO5 are left available for i2c.

## The display

When no countdown is running and the buttons are not used, time, temperature and humidity are display in a sequence. An unknown time is displayed as four dashes, invalid humidity or temperature is skipped. This is called automatic mode.

When one or more countdowns are running, these are displayed in sequence after humidity. The first countdown is shown in green, the second in yellow, the third in red. For the last 90 seconds, only the countdown is shown. As long as one countdown is running, the dash symbol flashes together with the colons.

A countdown with at least 100 minutes is displayed as hh:mm, then mm:ss.

## Using the buttons

Always: When one or more countdowns are signaling alarm via the buzzer, a single click to upper or lower button stops buzzing and countdown, skipping other actions.

In automatic mode.

| Button | Action |
| --- | --- |
| Upper single | Signal button press to Home Assistant |
| Lower single | Switch to countdown display mode, countdown 1 |

In countdown display mode:

| Button | Action |
| --- | --- |
| Upper single | Start or stop current countdown |
| Upper double | If current countdown is not running, goto countdown set mode |
| Upper hold | If current countdown is not running, goto countdown set mode |
| Lower single | Switch to display next countdown, or back to automatic after countdown 3 |
| Lower double | Back to automatic mode |
| Lower hold | If current countdown is not running, goto countdown set mode |

Countdown set mode is signalled by lighting the AM indicator. In countdown set mode:

| Button | Action |
| --- | --- |
| Upper single | +1min |
| Upper double | Start countdown, goto automatic mode |
| Upper hold | increase countdown time in 1min steps while holding |
| Lower single | -1min
| Lower double | Back to automatic mode |
| Lower hold | decrease countdown time in 1min steps while holding |

## HA API

For every countdown, these entities are exposed:

- Switch whether the countdown is running
- Remaining time as hh:mm:ss. The update frequency is dynamic to reduce network traffic: Every second for the last minute, or every 10 seconds for 1-10min, or once per minute.
- Alarm sensor
- Reset button to last time (I may remove this)

As long as less than three countdowns are running, a new countdown can be started via. Unfortunately, there is no error reporting:

- Entering the duration as hh:mm:ss or mm into the "new countdown" text field, then pressing "start new countdown"
- API action new_countdown with the number of seconds as parameter
- MQTT publish to .../new_countdown with the number of seconds

While in automatic mode, arbitrary text can be displayed via. Be aware that a seven segment display has only a limited character set:

- API action show_text with quite a bunch of options
- MQTT publish to .../show_text, either just the text or a json with a bunch of options

Naturally, misterblack1's effect entities are also exposed, however I removed the related HA actions. Also, HA sees stuff like a binary sensor for the exposed single click, switch to control the ambient light sensor, reboot, buzzer start, buzzer stop.
